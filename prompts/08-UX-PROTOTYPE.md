Use the existing stack if available; keep synthetic demo route or dev-only mode separate from the real application. Do not overwrite an implemented feature or build fake auth. This is a prototype, not a release.

Build meaningful local interactions (filters, favorites, comparison weights, budget simulator, RSVP filter, seat assignment within capacity, package selection). Ensure all controls usable with keyboard/touch, 320px layout and no inaccessible drag-only flow.

Inspect browser output/screenshots at desktop and mobile if tools available, run tests/build, document actual behavior and limitations; keep prototype code segregated from real domain/backend. Provide commands and route to view it. Record in status ledger as prototype, not completed production tickets.
