### 2026-11-20 · Claude Code · UX-04c (venue/vendor link lookup) · branch `main`

- **Scope and decision:** "Paste a link" on Add a venue/vendor: member presses "Look up this page"; the server reads that one page and prefills empty fields (name, location, source link, today's date as "last checked", and the page description and phone into Notes labelled "From host: ..."). Nothing is saved until the member saves; typed fields are never overwritten; no price, capacity, availability or rating is ever filled. Owner approved fetching on 2026-11-20; recorded in **ADR-029**, which supersedes ADR-003's "no scraping" and the R1 line in `docs/10-SECURITY.md` for this single user-initiated lookup only (security doc line updated).
- **Controls (`src/server/links`, `src/domain/links`):** URL rules (http/https, ports 80/443, no credentials, no IP-literal/localhost/single-label/.local/.internal hosts in any spelling); `isPublicAddress` via `net.BlockList` (v4/v6 private, loopback, link-local, CGNAT, multicast, reserved, documentation, Teredo, NAT64, 6to4, IPv4-mapped unwrapped); fetcher pins the connection to a validated DNS answer (no rebinding gap), refuses if any answer is non-public, re-validates each of at most 3 redirects, 8 s timeout, 512 KB cap on the decompressed body (zip-bomb safe), HTML only, no cookies, generic User-Agent with no personal data; one generic failure message so it can't probe the network; `site-rules.ts` per-site block list (empty today, for the owner's future rules); in-memory 10/min/member rate limit (per instance, resets on restart: documented limitation). Extraction is plain parsing (title, og tags, JSON-LD), outputs text only with tags, control and bidi characters and angle brackets removed. Requires `vendors.manage`. No migration, no new dependency.
- **Tests:** 40 unit/real-network tests: URL (hostile spellings), address policy (every range plus neighbours not over-blocked), site rules, rate limiter, extraction (including prompt-injection-style text, broken JSON-LD, truncation, pathological markup in linear time), form-filling rules, and the fetcher against real local HTTP servers (gzip, redirect, zip bomb, oversize, non-HTML, 404, timeout, redirect loop, redirect to private/file/credential targets, hostname resolving to loopback refused, and the strict policy never connecting to a local server by IP or name). 2 new Chromium e2e (bad and internal addresses give one honest message and keep typed input; Enter in the link box doesn't save; viewer can't reach the page).
- **Manual check (not a committed test):** one real lookup of `example.com` through the dev app filled Name "Example Domain", Source link and date, left a typed Location alone, saved nothing. This is the only live outbound request made.
- **Commands, exit 0:** `format:check`, `lint`, `typecheck`, `test:unit` 559; e2e (chromium) discover, quotes, compare specs.
- **Not decided / open:** robots.txt and per-site terms review (ADR-029 says the lookup reads one page a member could open in a browser; revisit before any bulk or scheduled use). Database-backed rate limiting. Hosting egress rules (a deployment firewall should also block internal ranges; this code is not the only layer you would want in production). Pages that need JavaScript to render will return little or nothing. Happy-path UI is covered by unit tests plus the one manual check, because the strict policy correctly refuses a local test server.
