# RSVP_SUBMISSION_TRACE.md

Read-only trace of one guest-submitted RSVP from planner setup to downstream planner views. Repository state: `main` @ `a8f8f41` plus the uncommitted REL-01 to REL-12 work in the working tree (audited as-is on 2026-11-22). Every hop cites code; "Observed" means a test or browser run on the local synthetic stack in this session exercised it (see EVIDENCE_LOG.md E-20 to E-24).

## Synthetic scenario

Fictional "Example" party: **Guest A** and **Guest B** (one household), invited to **Ceremony** and **Reception**, with **one allowed plus-one** on the Reception invitation. Reception has two meal options. Reception's seating plan is finalized; a catering count is locked.

> **Structural finding before the trace:** the app has no party-level, multi-event invitation. An invitation belongs to **exactly one event** (`supabase/migrations/20261130090000_events_rsvp.sql:53-75`: `invitations.event_id not null`). The party therefore receives **two separate links** (Ceremony, Reception) and answers each separately. Every answer is still per person and per event; that part matches the target.

## Late-cancellation scenario (brief p.2) against actual behaviour

Guest A changes Reception from Attending to Not attending after the seating plan was finalized and the caterer count locked.

| Brief expectation | Actual | Status |
|---|---|---|
| Confirmed count, seating demand, meal forecast, variable meal cost recalculate automatically | `event_demand` and `budget_item_counts` are computed on read; next page load shows the new numbers | Verified |
| Seating assignment flagged for **review** | Live seat is **removed automatically** (repo rule, `AGENTS.md` "A decline removes/archives active seating"); finalized snapshot kept, marked stale; one `seats_released` attention item | Verified (differs by design: auto-release + issue, not a review queue) |
| Shuttle, place card flagged | No transport module; place cards are generated on demand from the live plan | N/A / Missing |
| Meal-commitment discrepancy flagged | `caterer_count` drift item computed from locked vs yes | Verified |
| Guarantee, contract, invoice, payment, hotel unaffected | Guarantee immutable (test); commitments/invoices/payments not touched by replies (no RSVP code path writes them); no hotel module | Verified (guarantee), Partial inference (ledger: no write path exists) |
